# 강조 공백 보정 운영 인계 (MEG-197)

도구는 원격 쓰기를 실행하지 않는다. 기본은 읽기 전용 조사이며, 검토한 계획의
SHA-256과 사람이 수락한 후보 ID 목록이 있어야 적용/복구 SQL을 생성한다.
Markdown만으로 의도를 단정하지 않는다. Notion 원본 대조 또는 후보별 사람 수락을
제한된 운영 기록에 남긴다. 전체 본문 재가져오기·일괄 정규식 치환은 하지 않는다.

## 조사와 검토

1. MEG-170 적용 여부와 최신 상태를 확인한다. 다른 편집이 있으면 기존 계획을
   폐기하고 다시 조사한다. SQL을 준비한 순서대로 무조건 실행하지 않는다.
2. 운영자가 저장소 밖의 접근 제한 폴더를 준비한다. 원문·diff·백업·승인 목록을
   공개 PR/이슈에 첨부하지 않는다. 폴더 권한과 보관/폐기 책임은 실행자에게 있다.
3. `backend/`에서 환경변수 `EMPHASIS_AUDIT_URL`, `EMPHASIS_AUDIT_SECRET_KEY`를
   설정하고 다음을 실행한다. 키는 명령 인수·로그에 쓰지 않는다.

   `uv run python -m scripts.emphasis_recovery --out-dir <제한된-새-폴더>`

   `--snapshot <JSON>`을 주면 원격 조회 없이 `{id, revision, body_markdown}` 행 배열을
   사용한다. 실제 조회는 GET만 사용하고 id keyset으로 빈 페이지까지 조회한다.
   스냅샷은 조회 시점의 복제이며 일관된 DB 백업을 대신하지 않는다.
4. `report.json`의 후보·제외 사유·위치·diff를 검토한다. 단순한 한 줄의 단일 강조만
   후보로 내며 코드·링크·이미지·이스케이프·정상 강조·복잡한 경계는 자동 적용하지
   않는다. 후보가 없다는 사실은 전체 문서가 정상이라는 증거가 아니다.
   문서 전체의 블록/인라인 문맥으로 혼합 공백·탭 코드, 여러 줄 및 참조형 링크·이미지를
   보호한다. 정확한 인라인 원문 범위가 없으므로 보호 토큰/대괄호/코드가 있는 문단은
   통째로 제외한다. 같은 문단의 일반 강조도 제외될 수 있다. 제외 후보는 승인으로
   우회할 수 없으며 이전 버전의 계획도 다시 조사·검토해야 한다.
5. 의도가 확인된 후보 ID 문자열만 JSON 배열로 `approved.json`에 넣는다. 원본 검토
   근거·검토자·시각은 별도 제한된 기록에 남긴다. 조회 출력의 `plan_sha256`를 사용해:

   `uv run python -m scripts.emphasis_recovery --plan <plan.json> --approved <approved.json> --approve-plan-sha256 <해시> --out-dir <다른-새-폴더>`

## 적용·재개·복구

생성된 `backup.json`, `apply.sql`, `rollback.sql`을 사람이 검토한다. 승인 해시는
계획 동일성 확인용이며 전자서명이나 접근 통제 수단은 아니다. 원격 대상 자격증명은
실행자가 별도로 확인한다. 환경 혼동 방지를 위해 접속 대상·계획 해시·실행 ID를
운영 기록에 남긴다. 적용 직전 별도 DB 백업을 확보한다.

STG에서 합성/승인된 대상 리허설과 화면 확인 후 PRD 적용을 별도로 승인한다.
운영자는 PGHOST/PGPORT/PGUSER/PGDATABASE/PGPASSWORD/PGSSLMODE 등 환경변수로
접속을 설정하고 `psql -X -v ON_ERROR_STOP=1 -f <apply.sql>`을 실행한다.
psql 출력의 실행 ID·노트별 상태와 마지막 `committed`를 제한된 로그에 보관한다.
실패 시 SQL 오류 문맥에 원문이 포함될 수 있으므로 로그도 공개하지 않는다.

- 한 패키지는 한 트랜잭션이다. 행 잠금 뒤 revision·원문·SHA-256을 확인한다.
  충돌/누락/권한/트리거 실패면 전체 롤백한다. 성공 notice만으로 커밋을 판단하지 않는다.
- 기존 revision·updated_at 트리거를 실행하고 같은 트랜잭션에서
  `ai_invalidate_explanations`를 호출한다. 해당 함수가 없거나 실행 권한이 없으면 실패한다.
- 정확한 적용 후 본문과 revision일 때만 재실행을 건너뛴다. 그룹 일부가 이미
  적용된 상태에서도 이미 적용된 행의 revision을 추가 증가시키지 않는다.
- 복구는 `psql -X -v ON_ERROR_STOP=1 -f <rollback.sql>`. 정확한 적용 직후 상태에서만
  복구한다. 복구 후 revision은 원본+2다. 재복구는 건너뛰며 이후 사람 편집·다른
  마이그레이션은 충돌로 거부한다. 미적용 행이 섞인 복구도 거부하므로 먼저 실행
  결과를 확인하고 실제 적용한 그룹에 해당하는 패키지만 복구한다.
- 본문 복구가 무효화한 AI 설명을 다시 활성화하지는 않는다.

## 사후 확인과 한계

새로고침한 실제 노트에서 Mermaid·강조·용어 링크·모바일/PC 선택 위치를 확인한다.
E05는 읽을 때 최신 본문으로 span을 계산하고, E09는 이전 revision 요청을 거부한다.
공유 설명은 행을 지우지 않고 무효화하므로 과거 신고/기록 참조를 보존한다.
클라이언트의 열린 탭은 외부 SQL 변경을 실시간 반영하지 않으므로 새로고침이 필요하다.

합성 회귀, 네트워크 격리 PostgreSQL의 실제 저장소 마이그레이션, 실제 E05 span 함수와
Playwright 렌더러를 검증한다. 브라우저 API 응답은 합성이다. 실제 STG/PRD 대상 수,
원본 의도 대조, 운영 적용·복구·사람 수락은 이 도구 PR의 검증으로 대체하지 않는다.
실행자는 대상 수·승인·백업·환경·실행 ID·성공/충돌/실패·화면 확인·수락을 별도 기록한다.
