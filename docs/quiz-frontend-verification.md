# 퀴즈 답변·꼬리 질문 화면 검증

MEG-178은 기존 오늘의 퀴즈 목록에 E12~E14를 연결한다. 새 API나 스키마를 추가하지 않는다. 기존 카드·입력·버튼·AI 상자를 사용하며, 목업과 다른 목록 내 전개 방식과 오류 안내 문구는 임시 구현이다. 한 문제씩 풀기·문제 저장은 별도 명세 범위다.

## 자동 검증

`frontend/`에서 실행한다.

```sh
npm ci
npm run lint
npm run build
npm run test:e2e:quiz
npx playwright test tests/quiz.spec.ts tests/loginPrompt.spec.ts tests/account.spec.ts
npx playwright test -c playwright.notes.config.ts -g 'E11|ready의 문항|퀴즈 카드'
```

퀴즈 전용 시험은 실제 브라우저 fetch 경로에 합성 HTTP 응답을 제공한다. 모바일·PC에서 답 제출, 정답·해설 표시, 꼬리 질문 두 차례 생성·답 저장, 재접속 복원, 중복 제출, 입력 경계, 오류별 안내, 화면 이탈·세션 변경을 확인한다. 실제 DB·Bedrock 성공을 증명하는 시험은 아니다.

## 로컬 실제 백엔드 e2e

위 시험은 합성 HTTP 응답을 쓰므로 실제 백엔드·DB·Auth를 거치지 않는다. 이 절의 시험은 로컬 Supabase, 실제 FastAPI, 실제 로그인 쿠키를 거쳐 E11~E14를 확인한다. Bedrock만 시험용 가짜로 바꾸며 실제 AI는 부르지 않는다(MEG-207).

준비는 한 번만 한다. [백엔드 로컬 가이드](backend-local-guide.md)의 `prepare`, `start`, `fixture`를 `backend/`에서 실행한다. 다른 로컬 환경이 포트를 쓰고 있으면 `prepare --base-port 57320`처럼 비어 있는 번호를 고른다.

실행은 `frontend/`에서 한다.

```sh
npm run test:e2e:quiz-local
```

시험이 직접 하는 일은 다음과 같다.

1. 시험마다 `scripts.local_quiz_e2e seed`로 member-a의 오늘(KST) 합성 세트와 문항 둘을 다시 만든다. 이 도구가 만든 세트 132100만 지운다.
2. 백엔드(8187번)와 Vite(4187번)를 띄운다. 백엔드는 AI 클라이언트만 가짜로 바꾸고, 퀴즈 시각을 오늘 12:00 KST로 고정해 08:30 이전에도 돈다. 그래서 `not_open` 응답은 이 시험으로 확인하지 못한다.
3. 합성 계정으로 로그인해 답 제출, 정답·해설, 꼬리 질문 두 차례와 답 저장, 새로고침 뒤 복원을 확인한다. 다시 제출(409), 남의 문항(404), 답하기 전 꼬리 질문(409)도 확인한다.

이 시험은 `tests-local/`에 있어 기본 `npm run test:e2e`와 CI에 포함되지 않는다. 로컬 Supabase가 없으면 실패한다. 꼬리 질문 답 원문 복원은 E11이 돌려주지 않으므로 확인하지 않고, 실제 Bedrock 성공은 staging 절차에서 확인한다.

## staging 검증 절차

1. 사람이 staging 대상 PR을 병합한 뒤 배포의 READY와 커밋 SHA를 확인한다.
2. 사용자가 지정한 로그인 계정에 오늘 세트가 있는지 확인한다. 기존 세트·답은 덮어쓰지 않는다. 없으면 staging 전용 합성 자료로 시험 세트를 준비하고 추가한 행 ID를 비공개 실행 기록에 남긴다. production 데이터는 사용하지 않는다.
3. 로그인한 `/quiz`에서 문항 하나에 합성 답을 제출한다. 정답·해설 표시와 DB `quiz_answers` 저장을 확인한다.
4. 꼬리 질문 1을 생성하고 답을 저장한 뒤 질문 2에 반복한다. 질문당 실제 AI 원장 정산과 저장 결과를 확인한다. 불필요한 반복 생성은 하지 않는다.
5. 새로고침하여 문항 답·정답·해설, 두 꼬리 질문의 저장 상태와 세 번째 생성 버튼이 없는지 확인한다.
6. 생성한 시험 자료와 잔여 검증을 기록한다. 정산 원장을 삭제하거나 기존 사용자 기록을 초기화하지 않는다.

E11은 꼬리 질문의 답 원문을 반환하지 않고 `answered`만 반환한다. 따라서 새로고침 후 꼬리 질문은 질문과 ‘답 저장됨’ 상태를 복원한다. 방금 저장한 답 원문은 현재 화면에서만 보인다. 자동 재시도로 AI를 다시 호출하지 않는다.

복구가 필요하면 해당 프런트 변경을 되돌리는 PR을 사용한다. 화면을 되돌려도 이미 저장된 답과 정산 원장은 유지한다.
