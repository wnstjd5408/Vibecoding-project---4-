# User Workflow (사용자 흐름) — CS 학습 노트 전체

> PRD 전에 채우는 공개 템플릿/요약. 승인된 Linear 원본이 우선한다. 고객 원문과 내부 결정은 여기에 복사하지 않는다.

- 문서 버전: v0.4 (2026-11-05). 변경 이력은 맨 아래 표
- 원본 참조: Linear 「CS 학습 노트 PRD v0.6」, 「CS 학습 노트 사용자 흐름 v0.1」, 「퀴즈 단일 문항·선택 저장·재풀이 사용자 흐름 v0.1」(MEG-160), MEG-186 「문서 기반 CS 학습 에이전트 — 디자인·사용자 흐름 v0.2」. 링크는 접근이 제한된 원본에 있다.
- 참조 버전/확인일: PRD v0.6 · 2026-11-05. PRD 1~3절(AC-1~AC-10)은 v0.5 기준으로 2026-10-21 사람이 수락했다(MEG-27). v0.6이 더한 퀴즈 범위(범위 9)와 AC-11~AC-14 문장, PC 화면 범위(범위 10)와 AC-15~AC-17 문장은 2026-11-05 사람이 수락했다. 실행 확인은 모두 남아 있다.
- 상태: 제품 전체(방문자·사용자·운영자)의 흐름을 글로 정리한 공개 요약이다. 화면 디자인은 별도 캔버스에 있고 5절에 짧게 연결했다. 사람이 흐름 전체를 이 버전으로 확인한 기록은 아직 없다. 실제 사용자 관찰은 없다(PRD 1절).

## 0. 진행 순서와 시작 조건

| 순서 | 산출물 | 시작 조건 |
|---|---|---|
| 1 | 사용자 흐름 (이 문서) | 검증할 제품 후보 1개가 정해짐 |
| 2 | PRD (`docs/prd.md`) | 이 문서의 1–4절이 채워지고 사람이 흐름을 확인함 |
| 3 | 디자인 (Claude Design) | PRD를 사람이 수락함. Claude Design 가용성을 확인함 |
| 4 | 백엔드 API spec | 이 문서의 2–3절을 사람이 확인하고 PRD를 사람이 수락함. 디자인과 병행할 수 있음 |
| 5 | 기술 검토·구현 | [spec-flow의 '탐색에서 개발로'](harness/spec-flow.md#탐색에서-개발로) 조건을 충족함. 디자인·API spec을 함께 검토함 |

각 산출물은 표의 시작 조건을 충족한 뒤에 작성하며, 디자인과 백엔드 API spec은 병행할 수 있다. 시작 조건이 충족되지 않았으면 해당 단계 섹션을 채우지 않는다. 특히 5절(디자인)은 PRD 수락 전에 비워 둔다.

## 작성 규칙 (AI 에이전트·사람 공통)

- 각 항목 끝에 근거 구분을 붙인다: `[사실]` 관찰·데이터로 확인됨, `[가설]` 우리 추정, `[미확인]` 아직 모름.
- `[사실]`에는 근거 위치(Linear 이슈 ID, 공개 가능한 자료명)를 함께 적는다. 근거 없는 수치·기간·비율을 만들지 않는다.
- 흐름 하나는 사용자 목표 하나를 다룬다. 목표가 둘이면 2절 표를 나눈다.
- 화면 모양이 아니라 사용자 행동과 결과를 적는다. 버튼 배치·색 같은 결정은 5절로 미룬다.
- 고객 발언 원문 대신 익명 요약을 쓴다. 원문은 접근이 제한된 Linear 원본에 둔다.
- Linear 원본과 이 문서가 다르면 원본을 따르고, 차이를 이슈에 기록한 뒤 이 문서를 고친다.

## 1. 대상 사용자와 사용 상황

- 사용자: 수업을 듣는 주니어 개발자·PM·SA 중 수업 외에 CS를 따로 공부하는 사람. 첫 로그인 사용자는 운영자가 계정을 발급한 3~4명이다. [사실] (PRD 1·8절, 2026-10-20 결정)
- 방문자: 로그인하지 않고 노트와 용어 사전 설명을 읽는 사람이다. 즐겨찾기·AI 질문·퀴즈는 로그인해야 쓴다. [사실] (PRD 2절 범위 1)
- 운영자: 노트와 용어 사전을 채우고, 계정을 발급하고, 신고를 처리하는 한 명이다. [사실] (PRD 8절)
- 사용 상황: 노트를 읽다가 모르는 용어를 만날 때, 그리고 헷갈린 용어를 다시 볼 계기가 필요할 때. [가설] (PRD 1절)
- 사용자가 이루려는 목표: 노트를 막힘 없이 읽고, 헷갈린 용어를 다음 날 퀴즈로 복습한다. [가설] (PRD 1절)
- 지금 쓰는 대안·우회 방법: Notion·블로그·검색. 다음 날 퀴즈를 풀러 다시 올지도 확인하지 않았다. [미확인] (PRD 1절 반례)
- 근거:
  - 운영자의 Notion 학습 노트가 실제로 있다. [사실] (MEG-27, 2026-10-19 확인)
  - 고객 인터뷰와 사용 데이터는 없다. 내부 아이디어이고 PMF 실험은 생략했다. [사실] (PRD 1절)
  - 10문항을 한꺼번에 보여 주는 퀴즈가 부담스럽다는 사용자 피드백이 한 건 있다. [사실] (MEG-160)
  - 한 문제씩 보여 주면 부담이 줄고 복습이 늘어난다는 효과는 검증하지 않았다. [미확인]
  - 선택 영역의 AI 설명이 짧고 부실해 학습 가치가 부족하다는 사용자 피드백이 있다. 별도 사용성 시험 결과는 아니다. [사실] (MEG-186)

문서 옆에서 질문하는 흐름(F6)의 사용자와 상황은 다음과 같이 따로 적는다.

- 사용자: 노트를 읽는 비전공자 학습자 [가설] (MEG-186)
- 사용 상황 (흐름이 시작되는 계기): 노트를 읽다가 이해가 막히는 용어·문장을 만난다 [가설] (MEG-186)
- 사용자가 이루려는 목표: 노트를 떠나지 않고 개념의 원리·사용 상황·제한을 이해하고, 이어서 질문한 뒤 읽기로 돌아간다 [가설] (MEG-186)
- 지금 쓰는 대안·우회 방법: 선택한 용어의 짧은 AI 설명과 대표 위키 열기 [사실] (현재 제품 동작, MEG-186)
- 설명 깊이에 대한 사용자별 선호, 문맥 추출·검색 품질, 대화 사용률과 이해도 향상은 [미확인]이다. (MEG-186)

## 2. 핵심 흐름

흐름 여덟 개를 다룬다. 방문자·사용자 흐름(F1~F3, F6), 퀴즈 두 흐름(Q1·Q2), 운영자 흐름(F4·F5)이다. F1~F5 번호는 Linear 사용자 흐름 원본과 같다.

모바일과 PC(Windows 브라우저)에서 흐름은 같다. PC 화면은 MVP 범위에 들어간다(PRD 범위 10, AC-15~AC-17). [사실] (2026-11-05 사람 수락) 흐름·권한·저장 데이터는 모바일과 같고 배치만 다르다. PC 폭은 1024px 이상이고 그 미만은 모바일 배치를 쓴다. 헤더 '퀴즈' 메뉴, '이어서 풀기' 버튼, 풀이 화면의 왼쪽 문제 목록은 범위에 넣지 않는다. [사실] (PRD 2.2절) 로그인한 사용자는 PC 목록 화면의 '오늘의 퀴즈'로 퀴즈에 들어간다. [가설] (AI 제안, 사람 확인 전) 실제 Edge·Chrome 확인은 하지 않았다. [미확인]

### F1. 노트를 읽다가 용어 설명을 본다 (방문자·사용자 모두, 로그인 불필요)

- 시작 조건: 배포 URL에 접속한다.
- 끝 조건: 용어 설명을 보고 노트로 돌아와 읽기를 이어 간다.

| 단계 | 사용자 행동 | 시스템 반응 | 막히는 지점·감정 | 근거 구분 |
|---|---|---|---|---|
| 1 | 과목을 고른다 | 그 과목의 노트 목록을 보여 준다 | 원하는 노트를 찾기 어려울 수 있다 | 반응 [사실] (PRD 범위 2), 막힘 [가설] |
| 2 | 노트를 연다 | 본문을 보여 준다. 사전에 있는 용어는 링크로 표시한다 | 링크 표시를 알아보지 못할 수 있다 | 반응 [사실] (PRD 범위 3, AC-4), 막힘 [가설] |
| 3 | 링크된 용어를 누른다 | 사전 설명(글·이미지)을 시트로 보여 준다. 로그인한 사용자는 열람 기록이 남는다 | 설명이 부족하면 어디서 더 보는지 모른다 | 반응 [사실] (PRD 범위 7, AC-4), 막힘 [미확인] |
| 4 | 시트를 닫고 읽기를 이어 간다 | 노트의 읽던 위치로 돌아온다 | 읽던 위치를 잃을 수 있다 | [가설] |

시트의 "전체 보기"(전체 화면으로 열기)는 사용자 요청이 있었지만 개발 범위에 넣을지 정하지 않았다. [미확인] (Linear 사용자 흐름 원본 4절, MEG-76)

### F2. 사전에 없는 말을 AI에게 묻는다 (로그인 필요)

PRD v0.6은 이 흐름을 "AI 설명"(드래그로 선택 → 짧은 AI 설명)으로 적고 있다. 2026-11-04 사용자 결정(MEG-186)으로 'AI 설명'은 'AI에게 질문'(F6)으로 대체한다. 이 결정은 PRD에 반영하지 않았다. [미확인] 아래 표는 PRD v0.6 기준이며, 대체 후의 흐름은 F6이다.

| 단계 | 사용자 행동 | 시스템 반응 | 막히는 지점·감정 | 근거 구분 |
|---|---|---|---|---|
| 1 | 사전에 링크가 없는 단어를 드래그로 선택한다 | 설명을 요청하는 동작을 보여 준다 | 드래그할 수 있다는 것을 모를 수 있다 | 반응 [사실] (PRD 8절 2026-10-21), 막힘 [가설] |
| 2a | (로그인 상태) 요청한다 | "AI 생성" 표시가 붙은 설명을 보여 준다 | AI 설명을 믿어도 되는지 불안할 수 있다 | 반응 [사실] (AC-5), 감정 [가설] |
| 2b | (비로그인 상태) 요청한다 | 로그인을 안내하고 AI를 호출하지 않는다 | 계정이 없으면 막힌다 | 반응 [사실] (AC-5), 막힘 [가설] |
| 3 | 설명이 틀렸다고 보고 "오류 신고"를 누른다 | 신고가 운영자 신고 목록에 쌓인다 | 신고 뒤에 무슨 일이 있는지 모른다 | 반응 [사실] (AC-6), 막힘 [미확인] |

### F3. 열어 본 용어를 다음 날 퀴즈로 복습한다 (로그인 필요)

- 시작 조건: 로그인한 사용자가 용어를 열어 보거나 즐겨찾기했다.
- 끝 조건: 다음 날 퀴즈의 문항과 꼬리 질문에 답한다.

| 단계 | 사용자 행동 | 시스템 반응 | 막히는 지점·감정 | 근거 구분 |
|---|---|---|---|---|
| 1 | (당일) 시트로 용어를 열어 본다 | 열람 기록을 남긴다 | 기록이 남는 것을 모를 수 있다 | 반응 [사실] (PRD 범위 7), 막힘 [가설] |
| 2 | 헷갈린 용어를 즐겨찾기한다 | 저장하고 새로고침 뒤에도 유지한다. 다른 사용자에게는 보이지 않는다 | 즐겨찾기를 모아 보는 화면은 이번에 없다 | 반응 [사실] (AC-7, 비목표), 막힘 [가설] |
| 3 | (다음 날 08:30 한국 시간 이후) 접속한다 | 전날 열어 본·즐겨찾기한 용어로 만든 퀴즈를 보여 준다. 08:30 전에는 보이지 않는다 | 퀴즈가 있는 줄 모르고 지나칠 수 있다 | 반응 [사실] (AC-8), 막힘 [가설] |
| 4 | 문항에 답한다 | AI가 판단한 난이도(상·중·하)를 표시하고, 답한 뒤 정답·해설을 보여 준다 | 정답·해설을 답한 뒤에 보여 주는 것은 수락에 포함된 가정이다 | 반응 [사실] (AC-8, PRD 9절), 막힘 [미확인] |
| 5 | 꼬리 질문에 답한다 (문항당 최대 2개) | 답변을 바탕으로 면접처럼 더 묻는다. 맞음·틀림을 채점하지 않는다 | 맞는지 알 수 없어 답답할 수 있다 | 반응 [사실] (PRD 8절 2026-10-21), 감정 [가설] |
| 6 | 퀴즈가 틀렸다고 보고 "오류 신고"를 누른다 | 신고가 운영자 신고 목록에 쌓인다 | F2 3단계와 같다 | 반응 [사실] (AC-6) |

같은 문항은 이틀 연속 나오지 않는다. 대상 용어가 없으면 퀴즈가 없다고 안내한다. [사실] (AC-8)

### Q1. 오늘의 퀴즈를 한 문제씩 푼다 (로그인 필요)

PRD v0.6이 MVP에 더한 흐름이다(범위 9, 2.1절). 위 F3의 3~5단계를 "한 번에 한 문항"으로 바꾼다.

- 시작 조건: 로그인한 사용자가 오늘의 퀴즈를 연다.
- 끝 조건: 원하는 만큼 풀고 목록에서 진행 상태를 확인한다.

| 단계 | 사용자 행동 | 시스템 반응 | 막히는 지점·감정 | 근거 구분 |
|---|---|---|---|---|
| Q1-1 | 오늘의 퀴즈를 연다 | 현재 문제 하나와 진행 상태를 보여 준다 | 몇 문제가 남았는지 모르면 부담스러울 수 있다 | 한 문항 표시 [사실] (PRD 범위 9, AC-11), 진행 표시 방식 [가설], 막힘 [가설] |
| Q1-2 | 답한다 | 최초 답을 제출하고 정답·해설을 보여 준다. 꼬리 질문은 F3 5단계와 같다. 같은 문항에 다시 제출하면 거부하고 첫 답을 지킨다 | — | [사실] (AC-8, AC-11, MEG-92) |
| Q1-3 | 다음 문제로 이동한다 | 다음 한 문항을 보여 준다. 답하지 않고 넘어갈 수도 있다 | 건너뛴 문제를 잊을 수 있다 | 이동 [사실] (AC-11), 건너뛰기·이전 문제 이동 [가설], 막힘 [가설] |
| Q1-4 | 문제 목록을 본다 | 오늘 문제의 목록과 답함·저장 상태를 보여 준다 | — | [사실] (AC-11) |

### Q2. 원하는 문제를 저장하고 다시 푼다 (로그인 필요)

- 시작 조건: 로그인한 사용자가 자기 문제 목록을 연다.
- 끝 조건: 저장한 문제를 나중에 다시 풀고 정답·해설을 확인한다.

| 단계 | 사용자 행동 | 시스템 반응 | 막히는 지점·감정 | 근거 구분 |
