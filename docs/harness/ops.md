# 운영 절차 (ops)

`AGENTS.md`에서 옮긴 절차다. 이슈에 착수하거나 손을 뗄 때, 다른 세션과 충돌할 때, 계정·승인 예외를 다룰 때, CI를 구성하거나 실패→수정 시험을 할 때 읽는다.

## 동시 작업
여러 AI 세션(Claude Code, Codex 등)과 사람이 같은 이슈와 저장소를 동시에 다룰 수 있다. 서로의 기록과 변경을 덮어쓰지 않도록 아래를 지킨다.
- 이슈 하나는 한 세션이 맡는다. 착수할 때 이슈에 `AI 작업 중` 라벨을 붙이고 작업 기록에 세션 식별자·시작 시각·범위를 남긴다. 종료·중단·검토 요청으로 손을 뗄 때 라벨을 떼고 해제 기록을 남긴다.
- `AI 작업 중` 라벨이 있는 이슈는 다른 세션이 읽기만 한다. 필요한 변경은 담당 세션이나 사람에게 요청한다. 4시간 넘게 갱신이 없는 표시는 사람이 확인한 뒤 해제한다.
- 이슈 본문은 쓰기 직전에 다시 읽고 바꿀 부분만 수정한다. 본문 전체를 새로 써서 덮어쓰지 않는다. 부분 수정이 충돌하면 다시 읽고 한 번만 재시도하며, 또 충돌하면 멈추고 알린다.
- 이슈 상태는 담당 세션만 바꾼다. GitHub 자동화가 바꾼 상태는 [completion](completion.md)의 PR 자동화 절을 따른다.

## 계정과 승인
- AI 전용 GitHub 계정에는 저장소 쓰기 권한만 주고 관리자·ruleset 우회 권한은 주지 않는다.
- 사람 Code Owner가 변경 내용과 AC별 검증 근거를 검토하고 승인한 뒤 직접 squash로 병합한다. 필수 승인 1명과 Code Owner 리뷰 요구는 유지한다. 여기서 승인 분리는 AI 작성 계정과 사람 승인 계정의 분리를 뜻하며, 사람 리뷰어를 추가로 요구하지 않는다.
- 사람이 자기 계정으로 연 PR은 자기 승인이 불가능하다. 승인 요건을 낮추지 않는다. 예외로 bypass를 쓰면 PR에 사유·당시 검사 결과를 남기고, bypass를 기본 병합 절차로 쓰지 않는다.

## CI와 시험
- 첫 실행 가능한 제품 코드와 CI는 같은 draft PR에서 준비할 수 있다. 관련 로컬 단위/통합 테스트와 CI를 실행하고 실제 보고된 검사를 required checks에 연결한 뒤 병합한다. 확정된 명령은 `AGENTS.md`의 빌드 / 테스트 절에 추가한다.
- PR CI와 사람 리뷰는 병행한다. 문서 변경에서도 필수 check가 정상 결과를 내도록 구성한다.
- 실패→수정 시험은 공개 가능한 시험 산출물 이슈와 PR에 연결하고 시작/기대 상태를 기록한다. 실패 시험 PR은 병합하지 않고 닫으며 Linear 상태를 실제 단계로 복원하고 근거를 남긴다.
