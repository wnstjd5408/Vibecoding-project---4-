# 명세 흐름 (spec-flow)

`AGENTS.md`에서 옮긴 절차다. M·L 작업을 시작할 때, PMF 이전 실험용 구현을 할 때, 사용자 흐름·PRD·실험 문서를 쓸 때 읽는다.

## 명세 원본과 공개 문서
- 승인된 Linear 명세·실험 기록이 제품 요구사항과 결정의 원본이다. `docs/user-workflow.md`, `docs/prd.md`, `docs/experiments.md`는 공개 가능한 요약 또는 템플릿이다. 원본 참조·버전을 확인한다.
- 결정 원본은 기능 명세에, 작은 작업은 이슈 Summary에 한 번 기록하고 PR 리뷰·실행 로그를 링크한다.

## 탐색에서 개발로
- PMF 이전 실험용 구현은 검증 질문, 최소 산출물, 노출 대상·데이터 영향, 범위·종료/재평가 시점, 폐기/정식 개발 승격 결정자를 사람이 정한 경우에만 진행한다.
- 기능은 한 명세에 문제·근거/미확인, 사용자 결과, 범위·비목표, AC, 측정/관찰 방법, Plan, 사용자 흐름·프로토타입 버전, 기술 접근·의존성, 테스트·배포·복구 방법을 연결한다. 판단 기준은 근거 있는 수치 또는 관찰 가능한 질적 기준으로 적는다.
- PRD를 쓰기 전에 `docs/user-workflow.md`로 사용자 흐름을 정리한다. 디자인은 PRD를 사람이 수락한 뒤 시작한다.
- Plan 초안과 디자인 프로토타입을 함께 발전시키고 구현 전에 기술 검토를 받는다. Claude Design은 가용성을 확인한 뒤 사용하며 필요하면 와이어프레임으로 검토한다.
